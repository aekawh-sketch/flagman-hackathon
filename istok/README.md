# ИСТОК — сайт и панели ресторана, подключённые к складу «Флагман»

Пилотный клиент складской системы «Флагман». Бренд, города, адреса и телефоны вымышленные.

```
Сайт ИСТОК (витрина, корзина, трекинг) + панель ресторана (касса, заказы, курьер, бухгалтерия)
      │  /api/{kush|kan}/bb/...           — тот же контракт, что у старого сервера
      ▼
server/ :3001 — сервер ресторана: заказы, клиенты, бухгалтерия, Excel, живые события
      │  X-Api-Key «Сайт ИСТОК» с узкими правами
      ▼
Флагман :8080 — склад: партии, FEFO, стоп-лист, горячие предложения, антифрод
```

## Что даёт склад сайту

| На сайте | Откуда |
|---|---|
| «Нет в наличии» и причина, «осталось N порций» | стоп-лист Флагмана, меню пересчитывается при каждом изменении склада |
| Заказ «всё или ничего» | Флагман проверяет и списывает продукты по FEFO; при нехватке — отказ: чего не хватает, «максимум N», похожие доступные блюда |
| Цена в заказе | только из каталога сайта — подменить её из браузера нельзя |
| Статусы заказа | в обе стороны: панель → склад; «готово» на кухне Флагмана → сайт и трекинг |
| Отмена | до готовки — продукты возвращаются в те же партии; после — себестоимость в потери с причиной |
| Склад | целиком во Флагмане (остатки, партии, приёмка, списания, пересчёт, аналитика) — в панели ресторана его разделов нет |
| Списание (панель → «Списание») | напиток или блюдо по техкарте либо продукт; сотрудник вводит **личный PIN**, причину и фото — заявка уходит во Флагман от его имени (не от сайта); повара и кассира подписывает управляющий |
| Живые обновления | `/api/{loc}/bb/events`: гостю — склад и стоп-лист, персоналу — ещё и заказы |

Если склад недоступен, сайт продолжает работать: меню показывается без отметок наличия,
заказы принимаются и досписываются на складе, когда связь вернётся (повтор безопасен —
Флагман узнаёт заказ по номеру).

## Запуск

Нужны Node 22 и PostgreSQL 16. Сначала запустите Флагман (`../flagman`, см. его README) — в нём
ключ сайта задаётся в `backend/config/application.yml` (`stock.site-api-key`).

```bash
createdb istok_kush && psql -d istok_kush -f server/schema.sql
createdb istok_kan  && psql -d istok_kan  -f server/schema.sql
cd server && npm install && npm start
```

`server/.env` (не в git):

| Переменная | Что это |
|---|---|
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` | Postgres |
| `DB_NAME_KUSH`, `DB_NAME_KAN` | базы заказов точек |
| `ADMIN_TOKEN` | служебный пароль владельца ИСТОК: вход в панель без логина (если склад недоступен) |
| `DB_NAME_EXT` | база заказов других ресторанов (по умолчанию `istok_ext`; создаётся сама) |
| `FLAGMAN_URL` | API склада |
| `FLAGMAN_API_KEY` | ключ «Сайт ИСТОК» — то же значение, что `stock.site-api-key` во Флагмане |
| `AUTO_FLOW` | демо: заказ сам проходит «Принят» → «Готовится» |

- Сайт: http://localhost:3001/
- Панель: http://localhost:3001/panel/login.html — **общая для всех ресторанов Флагмана**. Сотрудник входит логином и паролем из «Флагмана» (админ заводит кассира, повара, управляющего там) и выбирает, где сейчас работает: ресторан и точку — панель показывает только те, куда его пригласили. Одно место работы — сразу в него; сменить — «Сменить место работы» в боковой панели.
  - Разделы — по роли в выбранном ресторане: касса — кассиру (ТЗ Флагмана: управляющему касса закрыта); заказы и курьер — кассиру, повару, управляющему, админу; списание — всем; бухгалтерия и очистка заказов — управляющему и админу. Те же права проверяет сервер.
  - **Точки ИСТОК** — как раньше: витрина и цены сайта, базы `istok_kush`/`istok_kan`, склад по ключу сайта.
  - **Точки других ресторанов** — меню, цены, «осталось N» и стоп-лист прямо со склада (позиция кассы — вариант блюда Флагмана); заказы — в базе `istok_ext` (своя схема на точку, создаётся сама при первом входе), склад — от имени вошедшего сотрудника: его роль проверяет Флагман. Если склад недоступен, такой заказ не принимается (досылать его потом некому).
  - Без логина — служебный пароль `ADMIN_TOKEN`: только точки ИСТОК, все разделы.
- Демо-учётки Флагмана: `demo-cashier`, `demo-cook`, `demo-manager`, `demo-admin`, пароль `demo1234`.
- Склад: http://localhost:5173 — демо-вход любой ролью

Без сервера сайт работает в демо-режиме браузера (`?mode=mock`): данные в localStorage, логин любой, пароль панели `istok`.

## Папки

- `site/` — редизайн сайта и панелей (статика, без сборки); `shared/js/api.js` — единственная точка общения с сервером. Списки выбора — `shared/js/picker.js`: табличка поверх обычного `<select>` (группы, подпись справа, поиск в длинных списках), как во Флагмане.
- `server/` — сервер ресторана; `lib/flagman.js` — клиент склада, `lib/catalog.js` — меню и сопоставление
  вариантов (размер на сайте → вариант склада: `nb1` + «Большая» → `nb1-2`), `lib/events.js` — живые события.
- `seed/` — каталог сайта (меню, фото, техкарты); из `seed/menu.json` собирается и каталог Флагмана
  (`flagman/tools/build_seed.py`), поэтому названия и цены совпадают.
